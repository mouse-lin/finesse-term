# 词条契约

术语库的价值不在收了多少条，在每一条的 `trigger` 和 `trap` 写得对不对。定义谁都能抄，这两个字段抄不来。

---

## 十个字段

```json
{
  "id": "safe-area",
  "title": "安全区",
  "en": "Safe Area",
  "aliases": ["刘海屏", "Home 条", "底部横条", "safe-area-inset", "灵动岛"],
  "layer": "layout",
  "plain": "手机屏幕上被刘海、圆角和底部那根横条占掉的一圈，内容放进去就会被挡。",
  "say": "底部操作栏用 env(safe-area-inset-bottom) 预留安全区内边距。",
  "trap": "只写 position: fixed; bottom: 0 —— 全面屏上按钮被 Home 条压掉一半，而且模拟器看不出来，只有真机才暴露。",
  "pairs": ["viewport-meta", "sticky-footer", "tab-bar"],
  "trigger": ["按钮被挡住", "下面那条黑杠", "iPhone 上盖住了", "刘海挡住了"]
}
```

| 字段 | 是什么 | 硬要求 |
|:---|:---|:---|
| `id` | 稳定标识 | 小写字母 + 数字 + 连字符，全库唯一，定了不改 |
| `title` | 中文正名 | 一个，不要「安全区 / 安全区域」这种并列 |
| `en` | 英文正名 | 用于跨语种沟通和查资料 |
| `aliases` | 同一个东西的其它叫法 | 包含俗称和 CSS 属性名 |
| `layer` | 归属层 | 见下面的封闭集合 |
| `plain` | 大白话定义 | **一句话**，不用任何其它术语 |
| `say` | 可直接发给 Agent 的表达 | 见下 |
| `trap` | 最常见的翻车方式 | 见下 |
| `pairs` | 不一起做就会出事的搭档 | 必须指向库里已存在的 id |
| `trigger` | 用户会怎么描述这件事 | 见下 |

`surface`（`web` / `h5` / `both`）由所在文件决定，词条里不写；确需覆盖时才单独声明。

### layer 是封闭集合

`layout` · `interaction` · `state` · `component` · `motion` · `visual` · `a11y` · `perf` · `form` · `platform`

想加第十一个之前，先问它是不是这十个里某一个的下属。

---

## trigger：这个库的主键

**写用户的原话，不写术语。**

这个库和普通术语表的根本差别在这一个字段。普通术语表假设你知道要查什么；这里假设你**不知道**——你只有症状。

| ✅ 该写 | ❌ 不该写 |
|:---|:---|
| 「按钮被挡住」 | 「安全区适配」 |
| 「下面那条黑杠」 | 「safe-area-inset-bottom」 |
| 「点了没反应」 | 「缺少 Active 态」 |
| 「看着有点土」 | 「缓动曲线不当」 |

三条判据：

1. **是用户会说的话，不是你会写的话。** 判断方法：想象一个不懂技术的人在微信里跟你抱怨这件事，他打的那行字就是 trigger。
2. **不能是术语本身。** `title` 和 `aliases` 已经覆盖了正名检索路径，在 trigger 里重复一遍只会让匹配失真。`check` 命令会拦这种情况。
3. **四到六条，各不相同。** 同一个说法的近义改写没有意义——检索器用双字组覆盖率匹配，「按钮被挡住」已经能吃下「底部按钮被那条黑杠挡住了」。要补的是**不同角度**的说法（症状 / 位置 / 设备 / 情绪），不是同一角度的同义词。

写完了做一次自检：把这几条 trigger 交给 `find`，它们必须能查回这条词条本身，且不该把邻近词条挤下去。

---

## trap：多数时候比定义更值得说

**写「知道这个词的人也照样会犯的错」，不写「不知道这个词的人会犯的错」。**

后者是废话（不知道就是不知道），前者才是这个字段的全部价值。

| ✅ 有用 | ❌ 没用 |
|:---|:---|
| 「只做 Hover 不做 Active——手机上完全没有 Hover」 | 「不加 Hover 用户就没有反馈」 |
| 「锁滚动时直接给 body 加 overflow: hidden——iOS 会瞬间弹回顶部」 | 「不锁滚动会穿透」 |
| 「空状态只画一张灰图配『暂无数据』——这是新用户唯一会看到的一屏，却什么也没说」 | 「要记得写空状态」 |

优先收这四类：

- **平台差异** —— iOS 和安卓行为不同、模拟器看不出来、只有真机/特定容器才暴露
- **半成品** —— 做了一半等于埋雷（乐观更新不写回滚、截断不给出路、禁用不给原因）
- **过量** —— 这个手法本身没错，用多了就廉价（震动、错峰、强调色、二次确认）
- **张冠李戴** —— 和另一个术语混用（Tooltip / Popover、Chip / Badge、防抖 / 节流、Modal / Drawer）

一到两句写完。trap 不是文档，是一句能让人当场停手的话。

---

## say：可直接复制的那一句

`plain` 是解释给用户听的，`say` 是**用户转手发给 Agent** 的。所以：

- 用祈使句，说清做什么和做到什么程度：「底部操作栏用 env(safe-area-inset-bottom) 预留安全区内边距」
- 带上关键数值（时长、比例、阈值），因为这些正是用户说不出的部分
- **不绑框架、不绑组件库。** 出现 `<el-dialog>` 或 `useEffect` 就写坏了——这句话要在任何技术栈下都成立
- 一到两句，超过就说明这条词条该拆成两条

---

## pairs：不一起做就会出事

不是「相关阅读」，不是「你可能也想了解」。判据只有一条：

> **只做这一个、不做那一个，会不会出事？**

会 → 是 pairs。不会 → 不是，哪怕它们概念上很近。

H5 那册的 pairs 密度最高，因为移动端的坑几乎都是成对的。这也是 SKILL.md 门禁二的数据来源：`find` 返回的 pairs 必须一起说出去。

## 加一条新词条

1. 选册：移动端专属进 `h5.json`，小程序专属进 `mp.json`，动效和质感进 `motion.json`，盒模型、跨域、缓存这类前端基础概念进 `base.json`，其余进 `web.json`
2. 按上面的十个字段写全，`trigger` 至少四条
3. 双向挂 `pairs`——如果 A 的 pairs 里有 B，通常 B 的 pairs 里也该有 A
4. 跑 `node scripts/term.mjs check`，必须零问题
5. 在仓库根 `scripts/check.mjs` 的 `CASES` 里加一条检索用例，句子要用**口语**而不是术语
6. 跑 `npm test`，必须全绿

### 什么不收

- 后端、数据库、部署、构建工具的词——这个库只管看得见的那一层
- 某个框架/组件库的专有名词（`v-model`、`useState`、`el-table`）——换个技术栈就作废
- 只有定义没有 trap 的词——说明它还没常见到值得收
- 用户从来不会用大白话描述的词（写不出 `trigger` 就是这个信号）
